Student profile

Round 2. One page for every staff member. Each block appears only when the person looking holds its permission for this student's class. Role names never come into it: a teacher with every permission sees exactly what an admin sees. Turn on the labels to see which permission each block needs.

Is the child here today?The first thing a teacher or the front desk needs when a parent calls. It sits in the header as Present, Absent, Late or Not marked yet.
What does this child need from me?"Heads up" lists only the problems, worst first: overdue fees, a run of absences, missed homework, falling marks, plus any health note. Each one taps through to where you fix it. With nothing wrong, the card disappears.
How are they doing?One tile per area you're allowed to read: attendance, fees, results, homework. The tiles reflow, so two tiles fill the row and one tile spans it. Nothing shows as a lock.
Do it from hereCall, message, collect a fee, print the ID card. Each button needs its own permission, and the row shrinks to whatever is left.

Scope counts, not just the permissionAttendance permission held for Class 6 A only shows nothing on a Class 7 student. The server already refuses it, and the page hides that block the same way it hides a missing permission.
Hidden is not the same as failed"Not allowed" removes the block quietly. A failed load for any other reason keeps the block and shows Retry inside it, so the rest of the page still works.
Rows reflow, nothing goes greyThe action row draws 1–4 buttons, the tiles fill 2-up or span the full width, and ⋯ disappears when it would be empty. No locks and no disabled buttons, so nobody wonders what they're missing.
