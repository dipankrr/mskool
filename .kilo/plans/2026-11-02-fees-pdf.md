# Fee PDFs and printing: design for review

Status: **design only, nothing built.** Branch when approved: `feat/fees-pdf`, cut from the merged
fees overhaul. Mobile first. No payment gateway in this work.

## 1. How it works

```
Phone: Print or Share
   -> API fills the template with the school's data and returns finished HTML
   -> phone turns the HTML into a PDF (expo-print)
   -> Android's print screen, or the share sheet (WhatsApp and others)
```

- Templates live on the API, in `packages/services/src/fee-documents/`. A layout fix ships with an API
  deploy and needs no app release.
- No Chromium and no extra machine. If huge batches are ever needed, the same HTML can go through a
  server renderer later.
- Web can reuse the same HTML through browser print later, in about 50 lines. Not in this work.
- A template is plain data in, HTML text out, so it can be unit tested without a phone.

**New libraries:** `expo-print`, `expo-sharing` and `expo-file-system` (to name the file
`Receipt-RCP-2604-00003.pdf` instead of a random id) in mobile, which needs a new app build. `qrcode`
on the API. `apps/mobile/package.json` also holds the owner's script edit, so it gets staged by hunk.

## 2. The eight documents

| Document | What it shows | Who can print | Data |
|---|---|---|---|
| **Receipt** | School, receipt no., date, student, class, what was paid, discount, late fee, total, mode and reference, status stamp | `fee_payment:read` | `payment.detail` has it |
| **Student statement** | Every due, payment, discount and refund in the session, then the balance | `fee_report:read` | `dashboard.student` plus dues and payments |
| **Due notices** | One slip per student who owes: amounts due and overdue, previous dues, optional QR | `fee_report:read` | New read for a whole class |
| **Defaulter list** | Table of students who owe, by class and section | `fee_report:read` | Same read as notices |
| **Day book** | One day's collections by mode, refunds, and lines for signatures | `fee_report:read` | New read, by date |
| **Cheque list** | Cheques waiting to clear: number, bank, date, student, amount | `fee_payment:read` | `payment.list`, filtered |
| **No-dues certificate** | Student, session, statement that nothing is owed, date printed | `fee_report:read` | `dashboard.student` |
| **Fee structure sheet** | What a class pays, fee by fee and month by month | `fee_structure:read` | `structure.byId` |

**Rules**
- **Due notices:** only students who owe. The amount is due now plus previous dues, the same figure as
  the dashboard.
- **No-dues certificate:** refused unless nothing is due now, no previous dues remain and no cheque is
  waiting to clear. Unused future months must be cancelled first.
- **Status stamp on receipts:** CANCELLED, BOUNCED or REFUNDED, taken from the payment's current
  status. A partial refund prints the refunded amount rather than a stamp.
- **Money and dates:** existing paise maths and IST dates. A receipt prints what was recorded on the
  payment, never a recalculation.

Left out: refund voucher, collection report, tuition fee certificate, duplicate stamp and print log.

## 3. Paper

| Layout | Used for |
|---|---|
| A4 full page | Every document |
| A4 half, two copies (parent and office) | Receipt |
| A4 half, one copy, top half | Receipt, leaving the rest of the sheet for later |
| A4 half, one copy, bottom half | Receipt, using up a sheet already printed on the top |
| 2 or 4 per A4 | Due notices |
| Thermal 58mm or 80mm | Receipt |

- One template with different page styles, not separate documents.
- A receipt too long for half a page moves to a full page rather than being cut off.
- Thermal stays **untested on a printer**, since no printer is available. It's checked as a PDF on
  screen only. It reaches a printer through a PC or a print app. Direct Bluetooth printing is out.

## 4. School settings

A new Printing row under Optional in Fee setup, changed with `fee_structure:update`. One new table,
one row per school (migration `0045`). A school with no row gets the defaults.

| Setting | Default |
|---|---|
| Lines above the school name (trust name, "Recognised by…") | Empty |
| Lines below the address | Empty |
| Document titles ("Fee Receipt" can become "Money Receipt" or a regional title) | English titles |
| Footer text | Empty |
| Signature line wording | "Authorised signature" |
| Show amount in words (the number always prints) | On |
| Default receipt paper | A4 half, two copies |
| UPI QR | Off |

- **School name and logo always print**, from the school record, so a document can't lose its identity.
- **Length limits** on free text, so it fits 58mm paper.
- **Regional language:** the school types its own heading and titles. Labels and figures stay in
  English. Student names print as typed.

## 5. UPI QR

| Setting | What happens |
|---|---|
| **Off** | No QR |
| **School's UPI ID** | Each notice gets a QR holding `upi://pay?pa=…&pn=…&am=…&cu=INR&tn=<admission no.>`, so the amount and admission number are filled in |
| **Uploaded QR image** | The same image on every notice, and the parent types the amount |

- On due notices only, with a line telling parents to check the school's name in their UPI app.
- Nothing in the system knows a payment arrived. Staff record it like any counter payment.
- A later gateway adds a third option. Nothing here gets in its way.

## 6. On the phone

- A **Print or share** button on: payment detail and the receipt screen (receipt), the student page
  (statement, no-dues), Fee setup's structure page (structure sheet), and a new **Print** entry on the
  Fees screen (due notices, defaulter list, day book, cheque list).
- A sheet to pick paper and, for class documents, the class and section.
- Print opens Android's print screen, which has its own preview. Share makes the named PDF and opens the
  share sheet. **This replaces the custom preview screen I suggested earlier**, which would need another
  native library and adds little.

## 7. Safety

- **Tenancy:** every read goes through the existing scoped services and permission gates.
- **Escaping:** all school-typed text and student names are escaped in the HTML. A template test feeds
  in `<script>` and quotes.
- **Public data:** nothing here is public, and there is no link a stranger can open.
- **No writes:** printing changes nothing in the fee tables, so it can't touch the money.

## 8. Things to prove early

These decide whether the phone approach holds, so they come first, before the other documents:

1. **60 notices on a cheap phone:** how long it takes, and whether it finishes.
2. **Bengali and Hindi headings:** do letters join correctly with the phone's own fonts, or do we embed
   Noto fonts, which makes each file bigger?
3. **Very narrow pages:** does `expo-print` produce a clean 58mm PDF of the right length? It takes a
   fixed page height, so the API has to work out the height from the number of lines.
4. **Logo on 60 notices:** it must be embedded once, not 60 times.

If 1 fails, the fallback is limiting batches on the phone. If 3 fails, thermal waits. Neither changes
the rest of the design.

## 10. Questions for the owner

1. **Document titles:** one setting per document, as above, or only a receipt title? I'd keep all eight
   editable, since it's the same few lines of code.
2. **Default receipt paper:** A4 half with two copies, as above?
3. **No-dues certificate number:** I've left it unnumbered and unrecorded, since it only states today's
   position. Schools that file these may want a number, which needs a new table.
