## Slice: students backend (CRUD + roster names) — backend only

**Goal:** make students first-class API citizens so the admission flow (create student → enroll, using the existing `enrollment.*` endpoints) works, and so rosters carry student names. Guardians, portal login activation (ADR-007), siblings, and previous-school records are **explicitly deferred** — each lands with the flow that needs it.

**Established facts this builds on:** the `students` table is complete (Phase 1 migration; unique `(schoolId, admissionNumber)`; `status` enum with `active` default); `student.service.ts` exists with the B6 adapter `getStudentOwnerId`; `resolveStudentOwner` already sits in `trpc.ts` (S4.2); `student:create/read/update/delete` permission strings exist and `student:delete` is SENSITIVE (cache bypass is automatic); students are NOT scope nodes and carry denormalised `organizationId` + `schoolId`.

### Chunk 1 — `feat(contracts): students`
`packages/contracts/src/contracts/student.contract.ts` (drizzle-zod, house style):
- **create**: `admissionNumber` (required — school-issued, unique per school via the index, refused by the DB not pre-checked per ADR-022), `firstName`/`lastName`/`dateOfBirth` (isoDate)/`gender` required; all demographics/address/emergency fields optional; `admissionDate` optional. Omit `status` (defaults `active`), org/school, timestamps.
- **update**: partial; omit `admissionNumber` (school-issued identity — corrections are a deliberate school act, not a PATCH), `status` (transitions are the enrollment/TC flow's job), org/school, timestamps.
- Barrel wired.

### Chunk 2 — `feat(services): students`
Extend `packages/services/src/student.service.ts` (which keeps its B6 adapter):
- `createStudent(scope, input)` — B5 `schoolId`; no scope node; org+school from scope.
- `listStudents(scopes, q?)` — **school-level, `atSchoolLevel` widening** (students have no class/section columns — the entity-shape reasoning documented in academic.service); active-only; optional text search on name + admission number (`ilike`).
- `getStudentById(scope, id)` (no active filter — deactivated students stay readable, hard rule 2), `updateStudent`, `deactivateStudent` (sets `status: "inactive"`).
- Per-table `STUDENT_SCOPE_COLUMNS` (the S2.4 lesson, written in the docstring).
- **Roster names:** `enrollmentService.listEnrollments` gains an `innerJoin(students)` and returns `{ enrollment, student }` per row — rosters are enrollment-driven per DOMAIN.md, and the UI needs names. This changes the list output shape; the integration tests and smoke dataChecks adapt in chunk 4. The portal's `listEnrollmentsForStudents` stays unchanged.

### Chunk 3 — `feat(trpc): students`
`packages/trpc/src/routers/student.router.ts`, registered root-level as `student.*`:
- `list` (`staffListProcedure("student:read")`, permissive, optional `q`), `byId` (`resolveStudentOwner` + overlap — already built), `create` (B5 explicit `schoolId`, `student:create`), `update` (owner-resolved, cover), `deactivate` (`student:delete` — SENSITIVE, so the gate re-reads fresh automatically; POST to sub-resource, hard rule 2).
- OpenAPI meta + output on every procedure; no `scope_nodes` writes; no authz changes needed (all four permission strings exist).

### Chunk 4 — `test: students in integration, smoke, and seed`
- Integration: exact `student.list` rosters per role (note: all roles hold `student:read` EXCEPT `staff_coordinator` — its FORBIDDEN cell is part of the pin); byId cross-tenant indistinguishability; duplicate admission number → CONFLICT (add a `students_school_admission_number_uq` entry to `translateErrors`); deactivate semantics; happy-path create through the real `createStudentSchema` (self-cleaning via deactivate).
- Adapt the existing enrollment-list assertions (integration `okIds` + smoke dataChecks) to the new `{ enrollment, student }` shape.
- Smoke: `student.list` cell for all eight roles; byId pair.
- Seed: `findOrCreateStudent` routes its create through `studentService.createStudent` (find-first stays raw).
