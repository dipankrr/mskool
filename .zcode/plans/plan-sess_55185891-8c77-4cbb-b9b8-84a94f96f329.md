## Move `countsTowardResult` / `isGradedOnly` from `subjects` to `class_subject_mappings`

**Decision being implemented** (agreed in discussion): the flags answer "does THIS class's Maths count THIS year?" — a per-class, per-year fact — so they live on the per-(year, class, subject) row. Exam schedules inherit from the mapping and get no override of their own (supersedes the reference SQL's "inherited from subject but can be overridden per schedule"). Nothing consumes the flags anywhere in the codebase today, so the move is low-risk.

### Steps

1. **Schema** (`packages/db/src/schema/academic.ts`)
   - Remove `countsTowardResult` and `isGradedOnly` from `subjects`; update the table comment (category stays as identity; category is a creation-time seed for the flags, not a read-time source).
   - Add both columns to `class_subject_mappings` with comments stating: two independent booleans (all four combinations legitimate); single source read by the future exam chain; snapshot-at-computation semantics; no exam-schedule override (ADR reference).
2. **Migration** — `pnpm db:generate`, then hand-edit the generated SQL: before dropping the subject columns, `UPDATE class_subject_mappings m SET counts_toward_result = s.counts_toward_result, is_graded_only = s.is_graded_only FROM subjects s WHERE m.subject_id = s.id` so existing rows inherit their subject's values. Verify with `pnpm db:migrate` on the dev DB and `pnpm db:verify`.
3. **Contracts / services** — the type chain (db → contracts → services) propagates the change; fix any explicit field lists that break. The mapping create path in `assignment.service.ts` already spreads input into the row. `pnpm check-types` is the gate for finding every break.
4. **Docs** — new ADR in `docs/DECISIONS.md` recording the decision and the exams-phase rules (no schedule override; snapshot flags into result rows at computation; forbid `isGradedOnly` flips once component results exist; pass computation must skip graded-only subjects). Correct the `subjects.counts_towards_result` mention in `docs/DOMAIN.md`. Update `docs/TASKS.md` resume point.
5. **Gates** — `pnpm check-types`, `pnpm lint`, `pnpm test` all green.
